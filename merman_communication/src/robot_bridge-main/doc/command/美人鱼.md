## 二、控制消息格式

云端控制发到：

```text
robot/ctl/{robot_sn}
```

本地语音控制发到：

```text
robot/loacl/ctl/{robot_sn}
```

Payload 统一格式：

```json
{
  "uid": "cmd_001",
  "robotSn": "{robot_sn}",
  "commandType": "CONTROL",
  "action": "jump_to",
  "params": {
    "pointId": 13
  },
  "remark": "optional",
  "timestamp": 1710000000000
}
```

字段规则：

- `action` 是控制动作名。
- `params` 必须是对象；无参数时传 `{}`。
- 不使用 `param`。
- voice 发送控制消息不带 `source`。
- 云端和本地来源通过 MQTT topic 区分。

## 三、当前支持的 action

| action | 参数 | ROS2 输出 |
| --- | --- | --- |
| `jump_to` | `params.pointId` | `/tour_cmd/jump_to`，`std_msgs/msg/Int32` |
| `forward` | `{}` | `/cmd_vel_web`，持续发布 Twist |
| `back_off` | `{}` | `/cmd_vel_web`，持续发布 Twist |
| `turn_left` | `{}` | `/cmd_vel_web`，持续发布 Twist |
| `turn_right` | `{}` | `/cmd_vel_web`，持续发布 Twist |
| `stop_move` | `{}` | `/cmd_vel_web`，持续发布 Twist |
| `publish_mission` | `mission_id/preemptive/waypoints` | `/mission_topic`，`evbhuman_interfaces/msg/MissionArray` |
| `audio_done` | `data/value/station_id/stationId/id` 任一 | `/audio_done`，`std_msgs/msg/Int32` |
| `return_guest_area` | `{}` | `/robot/go_welcome`，`std_srvs/srv/Trigger` |
| `return_charging_position` | `{}` | `/robot/go_charge`，`std_srvs/srv/Trigger` |

暂未接入：

- `photograph`
- `voice_reply`，只由 voice 项目处理，不由 `robot_bridge` 执行 TTS。

## 四、MQTT 控制示例

### 1. 跳转导航点

```json
{
  "uid": "jump_to_001",
  "robotSn": "{robot_sn}",
  "commandType": "CONTROL",
  "action": "jump_to",
  "params": {
    "pointId": 13
  },
  "timestamp": 1710000000000
}
```

对应 ROS2：

```bash
ROS_DOMAIN_ID=99 ros2 topic pub --once /tour_cmd/jump_to std_msgs/msg/Int32 "{data: 13}"
```

### 2. 底盘控制

前进：

```json
{
  "uid": "forward_001",
  "robotSn": "{robot_sn}",
  "commandType": "CONTROL",
  "action": "forward",
  "params": {},
  "timestamp": 1710000000000
}
```

其他底盘 action：

- `back_off`
- `turn_left`
- `turn_right`
- `stop_move`

对应 ROS2：

```bash
ROS_DOMAIN_ID=99 ros2 topic echo /cmd_vel_web
```

### 3. 发布多任务

```json
{
  "uid": "mission_001",
  "robotSn": "{robot_sn}",
  "commandType": "CONTROL",
  "action": "publish_mission",
  "params": {
    "mission_id": "multi_5831_demo_v2",
    "preemptive": true,
    "waypoints": [
      {
        "id": 5
      },
      {
        "id": 8,
        "gesture": "introduction_gesture"
      },
      {
        "id": 3
      },
      {
        "id": 1,
        "gesture": "farewell_gesture"
      }
    ]
  },
  "timestamp": 1710000000000
}
```

`waypoints[].gesture` 可选，现场常用值：

- `welcome_greeting`
- `enthusiastic_presentation`
- `interactive_handshake`
- `introduction_gesture`
- `farewell_gesture`

### 4. 音频结束通知

voice 本地音频播放结束后会向本地控制 topic 发送：

```json
{
  "uid": "audio_done_001",
  "robotSn": "{robot_sn}",
  "commandType": "CONTROL",
  "action": "audio_done",
  "params": {
    "data": 2
  },
  "remark": "本地音频播放结束",
  "timestamp": 1710000000000
}
```

桥接会发布：

```bash
ROS_DOMAIN_ID=99 ros2 topic pub --once /audio_done std_msgs/msg/Int32 "{data: 2}"
```

### 5. 回迎宾位 / 回充电位

## 五、控制回执格式

回执 Topic：

```text
robot/info/{robot_sn}
```

回执规则：

- `commandType=CONTROL` 默认需要回执。
- 可通过 `needAck` / `need_ack` / `ack` / `requireAck` / `require_ack` 显式控制是否回执。
- 需要回执的消息必须携带 `uid`，回执会原样带回该 `uid`。

成功示例：

```json
{
  "uid": "jump_to_001",
  "success": true,
  "data": {
    "action": "jump_to",
    "message": "jump_to executed"
  },
  "timestamp": 1710000000000
}
```

失败示例：

```json
{
  "uid": "jump_to_001",
  "success": false,
  "data": {
    "action": "jump_to",
    "message": "jump_to 缺少 params.pointId"
  },
  "timestamp": 1710000000000
}
```

## 六、ROS2 到站事件转 MQTT

桥接订阅 ROS2：

```text
/station_arrival_detail
```

消息类型：

```text
std_msgs/msg/String
```

测试发布必须使用 `ROS_DOMAIN_ID=99`，不是 `DOMAIN_ID`：

```bash
export ROS_DOMAIN_ID=99
ros2 topic pub --once -w 0 /station_arrival_detail std_msgs/msg/String "{data: '{\"station_id\":2,\"play_audio\":true,\"action\":\"introduction_gesture\"}'}"
```

如果监听不到，先确认：

```bash
echo $ROS_DOMAIN_ID
ROS_DOMAIN_ID=99 ros2 topic echo /station_arrival_detail std_msgs/msg/String
```

桥接转发到 MQTT：

```text
robot/loacl/send/{robot_sn}
```

Payload：

```json
{
  "robotSn": "{robot_sn}",
  "topic": "station_arrival_detail",
  "data": {
    "station_id": 2,
    "play_audio": true,
    "action": "introduction_gesture"
  },
  "timestamp": 1710000000000
}
```

规则：

- 桥接对外事件使用 `topic + data`。
- 不在顶层放 `action`。
- `data.action` 只是事件附带动作，不是控制指令。

## 七、常见排查

### 1. `ros2 topic pub` 后桥接监听不到

确认 `ROS_DOMAIN_ID`：

```bash
export ROS_DOMAIN_ID=99
echo $ROS_DOMAIN_ID
```

### 2. 检查 ROS2 daemon

```bash
ros2 daemon stop
ros2 daemon start
```

### 3. 检查桥接服务

```bash
systemctl status robot-bridge.service --no-pager

docker logs -f robot-bridge
```

桥接服务需要稳定运行，并看到：

```text
已订阅站点到达: ros2 topic=/station_arrival_detail, msg_type=String
当前使用 ROS_DOMAIN_ID=99
```
